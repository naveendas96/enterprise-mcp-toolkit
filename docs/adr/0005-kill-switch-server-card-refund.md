# ADR 0005: Kill switch, server card and a fixed refund pipeline
**Decision:** The `@audit` wrapper checks a process-level kill switch first, then an allowlist server card, then the scope. `MCP_KILL_SWITCH` or `engage_kill_switch()` blocks every tool call immediately and writes `denied_by: kill_switch` to the audit log. The card (default `data/server-card.json`, override with `MCP_SERVER_CARD`) lists the servers and tools that may be called; anything else is denied and logged as `denied_by: server_card`. `request_refund` on `mcp-refund` always runs eligibility, a placeholder approval, then credit. The pipeline object raises if a step is skipped or reordered.
**Why:** Operators need one switch that stops an agent mid-run. A server card is the published allowlist a client can pin and that the server enforces. Refunds are a high-risk write, so the step order is fixed in code, not left to the model.
**Consequences:** New tools must be added to the server card or they are denied by default. The approval step is a stub that records an id; a real deployment would wait on a human or a policy engine.
